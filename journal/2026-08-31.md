### The day started with the product broken in front of the founder

"Right now my STATS GAMETIME is not working." A game was live and the site said
**No game tonight**, and when that was fixed there was still no way in.

It was three separate bugs stacked, and I called the cause wrong three times before
getting it right:

1. **Wrong:** blamed the sport default. Reverted after the gate went red.
2. **Wrong:** blamed a missing repaint.
3. **Right:** `paintHeroRibbon()` returned early on a passed tip without ever calling
   `put()`, so the ribbon kept whatever it had — which on first paint is nothing, and
   the screen behind it says "No game tonight". A game that has already started was
   the one state the function could not describe.

Then the second bug underneath it: **a one-game night had no door.** `#landingBtn`
called `startLive()`, which enters *the room you are already in* — and on a night with
one game the player was never in it. `playTonight()` now delegates to the hero's game
when the hero is showing a different room than the one loaded, with a one-per-load
latch so it can never bounce.

Then the third: the round screen promised **"Round 1 opens when the game tips"** on a
game that had already tipped. Copy that is a lie about the clock.

**All three are the same disease** — the one this codebase has had since B0. The
featured game and the room you are in are two different facts, and several places
each held their own opinion about which was which.

### Baseball asks at the end of every inning — and this is the one to remember

Founder, twice today: *"We want questions in baseball at the end of every inning."*
*"Ive said it multiple times."*

He had. And the **opposite was written in the skill file, twice** — "Use 3 rounds
(after the 3rd, 6th, 9th), not nine" — so every session read that, built three rounds,
and lost the instruction again. **A spoken instruction that contradicts a written one
loses every time.** The skill is corrected in both places and the decision is in
memory now.

It moved **eight copies** of the round structure: `TEMPLATES.baseball` tags/names/
worth/periods, `FAMILY.baseball.rounds`, `SPORTS.baseball` names/tags, `mlbSpan()`,
and the three prose screens that described the cadence in words. `mlbSpan` being the
single owner of the span is the only reason it was tractable at all — every resolver
reaches it through `mlbInSpan`, so one line moved all of them.

Three defects the change surfaced that would have shipped silently:
- the live ceiling **halved**, because `worth` is per QUESTION and nine rounds × two
  questions is not three rounds × two
- `qa/host-banks.js` kept `PERIODS = { mlb:[3,6,9] }` and **stayed green** while every
  "through three" question resolved over the 3rd inning alone
- band cutoffs tuned for a three-inning span answer "none" nearly every time over one
  inning — resolving perfectly, worth nothing to answer

### Four wrong causal calls in one day, and what they have in common

This is the honest part.

1. **Reverted the v7.5 faces for nothing.** Compared ONE run with faces (119/1) to ONE
   without (120/0) and called it causation. Measured properly: the check is 1-in-4
   flaky **both ways**. I removed a feature the founder had asked for on a single-run
   comparison of a flaky check. Restored.
2. **Blamed a 200ms `transition:padding-top`** for the same flake. Removed it, still
   3-in-5 red, reverted.
3. **Blamed Firestore contention, then agents, then concurrency** for a gate flake
   whose real causes were mine: three new suites waited on
   `typeof window.featureTonight === 'function'` and swallowed the timeout with
   `.catch(()=>{})` — both mistakes `qa/ready.js` exists to end — and **thirteen
   suites** set `SLATE.games` without stubbing `loadSlate`, so the live slate raced
   the fixture.
4. The tell I read past **twice**: those suites took **1780ms inside the gate** and
   ~10s standalone. A suite that finishes six times too fast did not run.

The common thread: **I reported a diagnosis before running the command that would
prove it.** That is already written in memory as `measurement_before_conclusion`, and
today is the day it cost the most.
